## Verdict

The code compiles cleanly, its 976 tests pass, and the rules that can be checked by search are mostly kept. But the
2026-11-26 batch claims much more than it delivers. It turned CI red on every platform, left a pack-signing trust hole,
added a second PDF engine against decision D3, and marked 167 features shipped, several of them backed by mocks or
working only in narrow cases. Phases 4 to 9 should be treated as **drafted, not done** until the items below are fixed
and each feature is accepted by hand.

## What is sound

- `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`, `cargo test --workspace` (976 passed, 0
  failed, 1 ignored) and `cargo deny check` all pass locally.
- MuPDF's raw bindings are used only inside `ecclesia-mupdf`; all 178 new `unsafe` blocks carry a `// SAFETY:`
  comment; the iOS and Android FFI entry points catch panics.
- Network calls are behind explicit consent (AI, translation) or start from a user action (open from a URL, Zotero,
  metadata lookup, classroom). Nothing calls out at startup.
- Localization: `en.json` and `ar.json` both have 2,136 keys; 1,145 `t!` keys are used and only `notebooks.empty` is
  missing. No literal UI strings were found in views.
- 743 of the 755 tests named in `docs/features.toml` exist in the code.
- Installer release 7 is 13.6 MB (budget 15 MB). The release exe starts and draws a PDF's first page in 7 of 7
  launches.

## Findings, most severe first

### Critical

1. **CI is red on Windows, macOS and Linux since the batch** (every run since `9e6218a`; green at `9a475ac`).
   - `sandbox::tests::malformed_fuzz_corpus_inputs_never_panic` needs `tests/fuzz/corpus`, which `.gitignore` (line 6)
     excludes. It exists only on this machine, so it passes here and fails on every runner.
   - On macOS, `page::canvas::tests::corpus_pdfs_render_non_blank_tiles_through_resize_scroll_and_zoom` fails
     (`crates/ecclesia-canvas/src/page/canvas.rs:2341`): tiles don't reach past 2000 px on a 3000 px view.
   - With CI red, nothing pushed since has been checked on macOS or Linux.
2. **Pack trust can be forged.** `crates/ecclesia-app/src/packs.rs` falls back to `FALLBACK_KEY_BYTES`
   (`d75a9801…511a`) when no key is set. That is the public key of RFC 8032's first Ed25519 test vector, whose
   private key is printed in the RFC, so anyone can sign a pack this app trusts. The trusted key can also be changed
   in `settings.toml`, where DD27 has it as a constant in the app. Fix: no fallback (packs disabled until the
   maintainer's key is compiled in), and no override from settings.
3. **A second PDF engine, against decision D3.** `crates/ecclesia-core/src/page_ops/pdf_doc.rs` (1,541 lines) is a
   hand-written PDF parser and writer used by 11 tools: redaction, compression, page operations, Bates numbering,
   headers and watermarks, encryption, content editing, CAD view, print production and notebook export. D3 allows
   MuPDF only, and D4 routes every document operation through the shim. Redaction's promise that nothing redacted
   remains rests on this parser, which decodes only Flate streams; it has not been tested against real-world PDFs
   (object streams, other filters, images partly inside a mark, incremental updates).
4. **"Sandboxed plugins" are not sandboxed.** `crates/ecclesia-features/src/plugins/runner.rs` starts a plugin with a
   plain `Command::new`, with the user's full rights. The Job Object sandbox in `ecclesia-core::sandbox` is not used
   for plugins. E.5 is marked shipped.

### High

5. **Statuses were raised without acceptance.** 167 features went to `shipped` in one commit (`ecb36b0`). AGENTS.md
   reserves `shipped` for features the maintainer has accepted. Several are not what their titles say:
   - **L.1 lecture audio and L.2 transcription:** the app holds `MockAudioCapture`, `MockAudioPlayback` and
     `MockTranscriber` (`crates/ecclesia-app/src/notebooks.rs:83`, `notebooks/phase5.rs:537`). Nothing is recorded
     or transcribed.
   - **O.15 validate signatures and O.20 PAdES:** the hand-written CMS and X.509 code accepts Ed25519 only
     (`signing/der.rs:750`). Signatures from real certificate authorities (RSA, ECDSA) report "unsupported", and
     Acrobat does not validate Ed25519 signatures either.
   - **O.4 OCR:** works on Windows, but starts a new PowerShell process per page and passes the page image through a
     temp file (`ocr/engine.rs:340`): slow, and fails where PowerShell is restricted.
   - **H.23 and H.24 handwriting recognition:** a hand-made glyph-prototype matcher for English only, with no
     measured accuracy.
   - **U.5 read aloud:** falls back to `MockSpeechSynth` when the system voice is not reached.
   - **K.11 and K.12 (iPad and Android canvases)** are marked shipped, but no device has run them and their CI
     workflows start only by hand and have never run.
6. **Speed budgets:** three of four are over (release build, median of 7, measured today).

   | Budget | Measured | Limit |
   | --- | --- | --- |
   | Cold start to usable window | 826 ms | 300 ms |
   | Open a typical PDF to first page | 162.8 ms | 150 ms |
   | Idle memory, one small document | 149.3 MB | 60 MB |
   | Core installer | 12.98 MB | 15 MB |

   No baseline has ever been recorded in `tests/perf/budgets.json`, so the regression gate (fail when 10 % worse)
   cannot fire. Cold start did improve from about 2,250 ms.

### Medium

7. **No record of the batch's own decisions.** None of these has a DD entry or a plan change, as AGENTS.md §1 and §9
   require: the second PDF engine; `opt-level = "z"` for most crates; the dual-scope installer with UAC; the
   "Vivaldi chrome" restyle; 300-tab hibernation; the replacement Home page; AI, OCR, translation and voices built
   into the core instead of packs (D8).
8. **Reviewability:** the batch landed as 20 commits of 7,000 to 24,000 lines, each spanning many tags. AGENTS.md
   asks for one tag per pull request. Several app files are large: `commands.rs` 3,291 lines, `pro_pdf_ui.rs` 2,569,
   `forms/model.rs` 2,657, `ecosystem_ui.rs` 1,991.
9. **Records:** 12 tests in `features.toml` don't resolve (the OCR, forms, signing panel and AI eval tests, and three
   CI workflow names). Five tags have no feature doc (K.16, U.8, K.19, V.12, K.25). V.2 and K.25 name no tests.

### Low

10. Cargo warns of four unused workspace dependencies (`ecclesia-cli`, `ecclesia-canvas-ios`,
    `ecclesia-canvas-android`, `ecclesia-app` listed in `[workspace.dependencies]`).
11. NASM is not installed locally, so libjpeg-turbo builds without SIMD (slower JPEG decoding in local builds only).
12. The locale key `notebooks.empty` is missing.

## Recommended order of repair

1. Make CI green: commit the fuzz corpus (or generate it in the test) and fix the macOS tile test.
2. Remove the pack-key fallback and the settings override.
3. Set every feature from the batch back to `in-progress` unless you have accepted it, and mark the mock-backed ones
   (L.1, L.2, U.5) and the narrow ones (O.4, O.15, O.20, H.23, H.24, E.5, K.11, K.12) plainly in their `open` notes.
4. Decide on the second PDF engine: move those tools onto MuPDF through the shim (MuPDF has redaction, page
   operations and saving), or approve it as an exception in the plan. Until then, don't rely on redaction for real
   documents.
5. Run plugins inside the sandbox, or mark E.5 not done.
6. Record a budget baseline, then work on cold start and idle memory.
7. Add DD entries for the batch's decisions so you can approve or reverse each one.
